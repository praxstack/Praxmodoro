Three defects, not polish

These are gaps against the written specification, in a milestone recorded as complete.

D1 · requirement with no implementation

The in-app “Motion: still” toggle does not exist

SPEC.md:19 lists it in M1 gate 5. openspec/specs/focus-loop-ui/spec.md:72 makes it an EARS scenario: “WHEN system Reduce Motion is on or the user selects “Motion: still””. No such control exists anywhere in app/Sources — only the OS-level accessibilityReduceMotion is read. M1 gate 5 was recorded PASS.

D2 · fixed at the model, dropped at the surface

Choosing a check-in answer does not bloom the field

The EARS scenario “Choice acknowledgement” requires one damped pulse when an answer is selected. AppModel increments fieldPulse correctly — but of seven CompanionFieldView( call sites, only FocusSurface and BreakSurface forward pulseSignal. CheckinSurface.swift:21 does not. The M1 validator caught exactly this class of bug and progress.txt records it fixed; the fix reached the model layer only. A test asserting fieldPulse == before + 1 passes whether or not any surface is listening.

D3 · dead code standing in for a behaviour

lastCheckinResponse is written and never read

Declared at AppModel.swift:114, assigned at :144, read by nothing — no surface, no test. The mock renders a live per-answer response message; the app shows a static line instead.

Why

There is a recorded deferral. It lives in two code comments — CompanionFieldView.swift:3-5 and SurfacePalette.swift:9-10 — both promising that the “exact color pipeline lands with the design-system pass in group 6”.

M1's actual group 6 is capability registry, copy lint, accessibility suite, network silence, provenance, and the final gauntlet. There is no colour or design-system task in it. M2's nine groups contain none either. The pointer names a phase that arrived twice and never carried the work, and it survived two milestones and nine independent-validator passes unflagged.

The deeper cause is structural. The only visual-adjacent EARS requirement, “Companion field physics”, specifies breath asymmetry, spring damping, drift and pulse count — all behavioural, all golden-testable, all golden-tested. It never mentions colour, blur, shadow or typeface. SPEC.md calls the mocks a “binding reference”, but that is prose in a preamble; M1's seven gates and M2's six gates contain zero visual-fidelity criteria.

A red→green→validator loop builds exactly what can be written as a failing assertion. Physics constants express beautifully. “Does this feel like the warm room in the mock?” does not — so it was never written, never failed, and never got built.

Five successive validators attacked the no-second-clock invariant with real, compiling counterexamples. None examined colour, motion or feel, because no criterion pointed them there. The interaction gaps — rewind/forward, hover, press, quick capture — were never even named as deferred; they appear in no spec, so test-first development had nothing to assert and produced nothing.

Remedy

  1. Fix D1–D3 first. They are spec violations, not polish.
  2. Make fidelity testable before building it. A design-system milestone that is only prose will fail the same way. Candidates: a DesignTokens layer derived from tokens.css by a checked-in converter with a parity test; per-surface snapshot images against committed references; an assertion that no view uses a literal colour, spacing or radius outside the token layer.
  3. Decide the typeface question. Bundle the three faces, or record “system fonts” as an accepted amendment. Right now it is neither.
  4. Retire the stale pointer. Replace both “group 6” comments with a linked atom, or delete the claim.
  5. Answer two product questions. Is the mock single-theme by design — tokens.css defines no dark variant, so the app's missing dark mode may be parity rather than a gap. And is rewind/forward wanted at all? A canonical-timestamp engine makes manual time-travel awkward to keep honest; that may be a good reason to drop it, but it should be recorded as one.

This page is set in the mock's own oklch tokens, with its --color-calm and --color-danger encoding parity states. Its typefaces are system stacks rather than Gabarito, Hanken Grotesk and Sono — the sandbox blocks font CDNs, which is a smaller version of the same decision the app never made.

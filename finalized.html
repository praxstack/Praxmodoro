Review without ceremony theatre

Risk-tiered review model

Not every atom needs a council. Every atom needs independent review. The review depth rises with semantic, privacy, timing, data-loss, accessibility, or release risk.

TIER 1 · STANDARD

Low-risk, locally reversible

  • One code reviewer
  • Machine OpenSpec trace
  • Focused + full CI
  • Task-level smoke
Examples · scaffolding, isolated visual tokens, docs-only correction
TIER 2 · SENSITIVE

Behavior or user-trust boundary

  • Code reviewer + domain reviewer
  • QA acceptance
  • Independent receiving audit
  • Specialist review where affected
Examples · reducer, time, persistence, entitlement, notifications, accessibility
TIER 3 · PROGRAM

Semantic or release decision

  • Blind multi-seat review
  • Adversarial second round
  • Independent chair / release authority
  • Digest-bound exact candidate
Examples · closed domain contract, data deletion, final release readiness
QA is present before code exists

Quality engineering across the whole cycle

QA co-authors scenarios, tests implementation slices, challenges integration, and owns release confidence. Smoke testing is a thin repeated proof, not a substitute for QA.

Where smoke testing belongs

Local atom

Immediately after focused and full green. Launch the exact Debug app with isolated state and prove the atom’s smallest user-visible outcome.

Pull request

Run the stable signed-app smoke plus affected-flow smoke. A UI runner timeout is red, not “probably okay.”

Nightly

Exercise sleep/wake, relaunch, reduced effects, multiple macOS configurations, data boundaries, and longer energy observation.

Milestone

Run the complete keyboard and VoiceOver focus loop from both main window and menu bar using a clean app-state root.

Release

Install the generated app on a clean account, run offline, inspect networking/entitlements/logging, validate rollback, and retain signed evidence.

Post-release

Run a tiny canary checklist against the shipped artifact. Any regression opens a new OpenSpec change or incident, never a silent patch.

Definition of a task

Every atom carries its own proof packet

A task is not a title. It is a closed contract that tells product, engineering, reviewers, QA, and release exactly what must change and what must remain untouched.

01Identity + outcome

Stable atom ID, user outcome, owner, priority, risk tier.

02OpenSpec references

Requirement and immutable scenario IDs owned by this atom.

03Scope boundary

Exact files, non-goals, dependencies, allowed adapters.

04RED contract

Command, expected failure, proof it selects real tests.

05Minimal implementation

Smallest complete behavior, no speculative infrastructure.

06Focused GREEN

Named tests and deterministic expected counts.

07Blast-radius GREEN

Full tests, build, format, generation, static and trace gates.

08Smoke contract

Exact user flow, environment, assertions, termination.

09QA matrix

Platforms, appearances, accessibility, interruptions, error paths.

10Review plan

Required roles, risk-specific specialists, receiving reviewer.

11Rollback + rescue

Failure mode, safe degradation, data and compatibility impact.

12Evidence + commit

Receipt paths, hashes, allowlist, conventional commit, ledger update.

FANG-like accountability

Roles and separation of duties

In a small autonomous team, these can be separate agent contexts rather than separate employees. The rule remains: the author cannot be the only approver of their own claim.

PRODUCT

PM / product owner

Owns problem, user value, scope, metric, non-goals, edition boundary.

Approves G0–G2 and release outcome.
TECHNICAL

Tech lead / architect

Owns DAG, architecture, interfaces, risk tier, rollback, operational integrity.

Approves G3–G4 and merge order.
DELIVERY

Implementer

Owns authentic RED, minimal complete code, focused/full green, evidence packet.

Cannot self-approve G7 or G9.
QUALITY

QA / SDET

Co-authors scenarios, owns smoke, automation strategy, exploratory and regression plans.

Approves G8 and release test evidence.
EXPERIENCE

Product designer

Owns hierarchy, states, interaction semantics, Liquid Instrument fidelity and fallbacks.

Required on UI and accessibility atoms.
TRUST

Privacy / security / accessibility

Reviews data minimization, entitlements, logs, export/delete, input, inclusive paths.

Risk-triggered approval, never decorative sign-off.
INDEPENDENCE

Code + receiving reviewers

Challenge correctness and audit the exact staged candidate, receipts, hashes, scope.

Own G7 and G9.
RELEASE

Release manager

Owns CI, clean artifact, rollback, support readiness, documentation and archive decision.

Owns G10.

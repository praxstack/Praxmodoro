# Design: add-session-settings

## Context

The 2026-08-12 settings-parity plan is the historical scope record. Current execution is governed by `docs/plans/2026-08-23-m3-validation-remediation.md` and the architecture-stabilization umbrella; those plans supersede the old parallel-lane and auto-push instructions. Product decisions retained from the applied dcanvas export `01KZTPM2DDFA8Q5ZM76ES0JXEJ`: autostart is a three-way user setting defaulting to prompt-first; rewind/forward is kept as an engine event; user notification text is verbatim; typography is separate. The engine's law — remaining time is `f(transitions, now)` — has survived six adversarial attempts against its guards this month; nothing in this change may weaken it.

Within the goal-ledger convention this file is the architecture record; `proposal.md` is the HLD and `tasks.md` the LLD.

## Goals / Non-Goals

**Goals:** every new time-shaped behaviour is an engine transition; every preference lives on the injected defaults seam; sound and notifications are pure presentation; the panes are token-ready without waiting for tokens.

**Non-Goals:** the Appearance pane (joins after lane 2), font bundling (#9), any new persistence schema, any UI-side scheduling.

## Decisions

1. **Adjustments are events, not offsets.** Rewind/forward appends an `AdjustmentRecord` to a log alongside the transitions (the clock-anomaly precedent — persisted transitions carry only a state name, so the magnitude needs its own record); `remaining(at:)` and `expiryInstant()` fold the current block's adjustments into the derivation. *Alternative — a mutable `bonusSeconds` on the session:* rejected; mutable state beside an event-sourced timeline is exactly how drift enters, and it would not survive the relaunch-reconstruction property.
2. **Autostart reuses the promotion machinery.** `reconciled(at:)` already inserts the gentle-start promotion at its canonical instant; the autostart break transition is the same shape gated on the behaviour setting, and the auto-return-to-focus transition (break end → focus offered, plan §Rhythm) is the same pass anchored on the break-end instant, off by default. Pure reconciliation inherits canonical timestamp correctness; task 10.7 separately proves the live root observation, sleep/wake, and relaunch-absence behavior after runtime C2. *Alternative — a separate app-layer expiry timer:* rejected; it would be a second clock and the guards ban it structurally.
3. **Prompt-first is presentation over a held engine.** In prompt-first mode the engine records expiry-hold (block complete, place kept) and the app shows a non-modal offer; accepting records the break transition at accept time, with provenance noting the offer. The engine never encodes "a prompt is showing" — that is surface state, like the return overlay.
4. **Behaviour setting read at expiry-processing time, not captured at begin.** Changing the setting mid-block affects the current block's end; least-surprise wins over snapshot semantics. Recorded here because it is the kind of ambiguity implementers otherwise decide silently.
5. **Sound is a transition listener.** `AudioCueScheduler` (AVFoundation) observes the same state changes surfaces render; ticking is an `AVAudioPlayer` loop started/stopped by state, never a `Timer`. The cue library has five rows: Block start, Focus tick, Break tick, Focus end, Break end. Each row contains its independent toggle and a trailing sample button with identifiers `sound-sample-block-start`, `sound-sample-focus-tick`, `sound-sample-break-tick`, `sound-sample-focus-end`, and `sound-sample-break-end`; each exposes the exact VoiceOver label `Play <cue name> sample`. Samples call the exact API `AppModel.previewSound(_ cue: SoundCue)`, which invokes the already-present `SoundCueScheduling.scheduleChime(_:at:volume:)` at the injected clock instant and current master volume without touching session state or preferences; no second playback abstraction is added. The factory-on set is block-start plus both end chimes at 0.7; both ticks and tick-loop remain off. Block-start fires only on a real transition into a new focus block (initial begin or return from break, including derived auto-return), never on relaunch or hold/resume. Chimes are scheduled ahead via `AVAudioPlayer.play(atTime:)`, whose device timebase can pause across sleep. Praxmodoro therefore observes the native `NSWorkspace.didWakeNotification` at the app root and calls the scheduler's cancellation seam before presentation resynchronizes; every pending chime whose canonical instant is at or before the injected wall clock is stopped and removed. An expiry that happened during sleep never retro-fires — a sound after the fact is noise, not information. No polling timer or second audio engine is introduced.
6. **Notifications are scheduled at canonical instants and cancelled on change.** `UNUserNotificationCenter` requests are created from `expiryInstant()` when a block begins or is adjusted, and cancelled/recreated on hold, adjustment, or setting change. The notification fires even if the app is quit — which is the point. While an asynchronous availability check is outstanding, existing scheduling behavior remains, but the callback is authoritative: a denied result sets the unavailable flag and immediately resynchronizes/cancels pending work before returning to the UI. Denied permission renders the toggles plainly unavailable; no re-prompt nagging.
7. **Preferences are two small value types** (`RhythmPreferences`, `SoundPreferences`) decoded from the injected `UserDefaults`, mirroring the Motion: still pattern; no new storage, no schema change, schema-parity tests untouched. `SoundPreferences` uses keyed decoding for the new `blockStart` field: a missing field decodes as `false` while every legacy master/toggle value remains intact. Only a missing or malformed whole preferences blob falls back to the new factory-on defaults. This prevents a compatible upgrade from silently enabling sounds or erasing prior choices.
8. **Panes use the existing token boundaries.** Pane colors come from `SurfacePalette` with `colorSchemeContrast` and Reduce Transparency; any explicit layout spacing or radius comes from generated `DesignTokens`. Domain numbers (minutes, cadence bounds, volume) and the fixed Settings window dimensions are not style literals. Actual-pane raster tests prove both accessibility environments, and the five sample actions carry cue-specific VoiceOver labels. This corrects the earlier “SurfacePalette only” wording, which was technically inconsistent because `SurfacePalette` exposes colors but no spacing roles.

9. **Remaining time is block-scoped** (as-built discovery). The session-wide `focusElapsed` made `expiryInstant()` re-derive a break at the very instant one ended — a latent defect auto-return would have amplified into a ping-pong. `remaining`/`expiryInstant` now derive from the current block (the last entry into running from a break); `focusElapsed` keeps the session-wide truth available (no surface consumes it yet).
10. **The root date-observation edge materializes derived transitions before presentation.** Every intent still materializes first. In addition, the root `TimelineView` passes its existing `context.date` to `AppModel.observeDerivedPhase(at:)` on every context-date change, not only when the derived phase differs. A phase-only callback is insufficient: sleep can span focus expiry, the complete break, and auto-return, leaving `.running` at both ends. The observer calls the existing canonical materialization once, then synchronizes sound/notifications; repeated dates are idempotent. This is not a second clock: it reuses the root rendering timeline and performs no duration arithmetic or scheduling.
11. **The caller proves when the rhythm was live.** `AppModel` captures `liveObservationStartedAt` from its injected clock at initialization. Core reconciliation receives both the explicit `autoReturn` Boolean and `autoReturnAfter: liveObservationStartedAt`; a canonical break end is eligible only when it is later than that boundary. A process that sleeps across the edge therefore materializes on wake, including a complete focus→break→focus cycle, while a process launched after the edge can never catch it up on its first or a later render. Restore itself passes `autoReturn: false` and never calls the observer. The Core `breakEndInstant(cadence:)` authority from runtime task 3 owns the comparison; the app adds no break arithmetic.

12. **Preset editing mutates defaults, never historical policy names.** Each preset row exposes an editable minute value and Remove. `availablePolicies` forms every user-reachable focus/break pair; if only one family has custom values, the other family uses the classic 25-minute/5-minute fallback. Removing or editing a preset affects future selection only because persisted custom policy names encode their durations. A store-backed relaunch test proves historical derivation remains unchanged.

13. **One pure predicate owns ordinary scheduled-player retention.** The internal function `shouldRetainChime(scheduledAt:now:isPlaying:) -> Bool` returns `isPlaying || scheduledAt > now`. `AudioCueScheduler` stores each pending player with its canonical scheduled instant, reads its injected clock once at the scheduling/pruning edge, retains future or currently playing entries, and removes stopped entries whose instant is not future. System wake is the deliberate exception: `cancelExpiredChimes(at:)` stops and removes every entry with `scheduledAt <= now` regardless of `isPlaying`, preventing the device timebase from emitting a stale cue. Both paths are event-driven and add no timer or audio framework.

14. **Preset minutes are bounded integers with quiet inline correction.** Focus and break presets both accept unique whole minutes in `1...240`; the shared range avoids two policies for one data type. Add or edit input outside the range, fractional text, or a duplicate is not committed. The field remains available with the persistent help text “Use a unique whole number from 1 to 240.” No modal error, clamping, silent truncation, or duplicate policy is introduced. Existing stored positive second values remain readable; validation applies when the user edits or adds.

## Data boundaries

No new persisted models. Session records gain nothing; autostart and auto-return reuse the existing transition vocabulary, and adjustments persist as a new `StoredEventKind.adjustment` value (a kind value, not a schema change — entities and attributes untouched). Preferences live in defaults; notification text lives in defaults; sounds are bundled resources.

## Dependency provenance

AVFoundation, UserNotifications, and the already-linked AppKit `NSWorkspace` wake notification are platform APIs. No third-party packages. Sound assets are original or CC0, committed under `app/Resources/Sounds/` with provenance noted in the commit.

## Rollback

Additive scenes and Core extensions. Removing the Settings scene and the one new stored event kind (`adjustment`) restores the pre-settings behavior; autostart and auto-return reuse existing lifecycle payloads. Sessions containing adjustments remain readable on the implemented branch, while the stricter runtime replay change rejects unknown lifecycle payloads rather than fabricating state.

## Verification strategy

Per-atom red→green via `./scripts/focused.sh`; Core work via `swift test --package-path app/Packages/PraxmodoroCore`. The no-scheduling and clock-read guards must stay green throughout — they are the proof that autostart and sound introduced no second clock. Focused coverage includes wake cancellation, deferred denial, actual-pane transparency/contrast rasters, and cue-specific VoiceOver/keyboard actions. Full gate `./scripts/verify-project.sh` plus `npm run spec:validate` strict at change completion, then the independent fresh-context validator before archive.
